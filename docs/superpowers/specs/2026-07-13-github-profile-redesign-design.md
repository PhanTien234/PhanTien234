## Contribution Snake Workflow

Replace the existing workflow with one job dedicated to generation and publication.

### Trigger and permissions

- Run on cron `0 */6 * * *`.
- Support `workflow_dispatch` for the initial run and manual recovery.
- Declare only `contents: write` permission.
- Set a short job timeout to prevent hanging runs.

### Generation

- Use `Platane/snk/svg-only@v3`, not an unpinned `@master` reference.
- Set `github_user_name` from `${{ github.repository_owner }}` rather than duplicating the username.
- Generate a standard light SVG and a GitHub-dark SVG with coordinated accent colors.
- Do not generate a GIF because the README only needs responsive, theme-aware SVGs.

### Publication

- Publish only the generated `dist` directory to the orphan `output` branch using `peaceiris/actions-gh-pages@v4`.
- Do not push generated files to `main` or `master`.
- Do not force-push the source branch.
- Remove the unnecessary checkout, `git status`, and legacy push steps from the current workflow.

## Data Flow

1. GitHub schedules the workflow or the owner dispatches it manually.
2. `snk` reads the public contribution graph for the repository owner.
3. `snk` writes the two SVG variants to `dist`.
4. The publishing step replaces the orphan `output` branch contents with `dist`.
5. The README `<picture>` element loads the matching raw SVG for the viewer's color scheme.
6. GitHub activity cards independently retrieve public profile data at render time.

## Failure and Degradation Behavior

- Before the first successful workflow run, the snake alt text remains meaningful even if the image URL is unavailable.
- A failed scheduled workflow must not modify `main`; the previous successful snake assets remain on `output`.
- If public stats endpoints are unavailable, the rest of the profile remains complete and readable.
- Local assets must use repository-relative paths so the hero does not depend on an image host.
- Scheduled workflows can be disabled by GitHub after prolonged repository inactivity; `workflow_dispatch` provides the recovery path.

## Files in Scope

- `README.md` - full replacement of the existing profile content.
- `.github/workflows/main.yml` - replacement with the modern snake workflow.
- `assets/` - repository-owned visual asset(s) required for the galaxy hero.
- `docs/superpowers/specs/2026-07-13-github-profile-redesign-design.md` - this approved design record.

No source repositories, CV files, GitHub account settings, pinned-repository settings, or unrelated profile repositories are in scope.

## Verification Plan

1. Run `git diff --check` to catch whitespace and patch defects.
2. Parse the workflow as YAML and run an Actions-specific linter when available.
3. Validate that the README contains no placeholder text, broken local asset paths, duplicated malformed URLs, fixed activity metrics, or unverified ranking claims.
4. Send HTTP HEAD/GET checks to external image and contact URLs where the remote host permits it.
5. Inspect the hero asset at full resolution and at a GitHub-like narrow width for text-free visual integrity.
6. Render or preview the README in a GitHub-compatible Markdown viewer, checking desktop/mobile structure and light/dark image selection.
7. After the implementation is pushed, manually dispatch `Generate Snake` once and confirm both SVGs exist on the `output` branch.

## Non-Goals

- Reproducing the supplied dashboard pixel-for-pixel with unsupported CSS or JavaScript.
- Claiming a GitHub percentile, trophy rank, coding hours, or manually calculated activity total.
- Adding unconfirmed frameworks such as Next.js, Redux, or Node.js to the core stack.
- Turning the profile README into a complete CV or duplicating employment history.
- Adding extra workflows beyond what the profile presentation requires.
